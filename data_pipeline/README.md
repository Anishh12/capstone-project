# Module — Scrape → Clean → Convert → Store → Query (books.toscrape.com)

## What this is
A raw-to-relational data pipeline: scrape a public book catalog, clean and type the fields,
convert price to INR at a fixed project rate, load into a normalized SQLite database, and
query it with both SQL and pandas.

## Files
| File | Purpose |
|---|---|
| `scrape_and_load.ipynb` | Scrapes books.toscrape.com, cleans fields, builds `books.db` |
| `queries.ipynb` | Runs 5 SQL queries against `books.db`, compares `pd.read_sql` vs `pd.merge` |
| `books.db` | SQLite database (regenerated by running `scrape_and_load.ipynb`) |

Run order: `scrape_and_load.ipynb` first (creates `books.db`), then `queries.ipynb`
(reads that same file). Requires `requests`, `beautifulsoup4`, `pandas`.

## Data source
`https://books.toscrape.com` — a public scraping-practice site, no login/API key/paid tier.

## Scraping scope
The first 5 categories listed in the site's sidebar (Travel, Mystery, Historical Fiction,
Sequential Art, Classics), paginated up to 5 pages per category. This produced **163 books**,
above the required minimum of 60 across at least 3 categories.

For each book: `title`, `price_text` (raw, e.g. `£57.62`), `rating_text` (`One`…`Five`),
`availability_text`, `category`.

## Cleaning decisions
- **`price_gbp`** — strip the `£` symbol (and the `Â` mojibake byte books.toscrape.com
  sometimes serves) and cast to `float`.
- **`rating`** — map the text rating (`One`…`Five`) to an integer 1–5 via a fixed dictionary.
- **`in_stock`** — `True` if the availability text contains "In stock", else `False`; stored
  as `0`/`1` in SQLite.
- **Bad-parse handling** (required by the spec, chosen per column):
  - `price_gbp`: **median-impute**. Price is a continuous field used in filters and sorts
    (Q4, Q2), so keeping the row with a robust central estimate is preferable to losing data.
  - `rating`: **drop the row**. Rating only takes 5 fixed values; fabricating one (e.g. via
    imputation) would misrepresent a book's actual star rating in every later filter/join.
  - On this run, 0 rows needed either fix (median price computed was £35.28 as a reference
    value, but no `price_gbp` cell was actually missing, and no `rating` cell failed to parse).

## Currency conversion
`price_inr = price_gbp * 105.50`. This is the assignment's fixed, project-defined baseline
rate (not a live/historical market rate) and needs no API call or date reference.

## Database schema
Two tables, normalized, linked by a primary/foreign key:

```sql
CREATE TABLE categories (
    category_id   INTEGER PRIMARY KEY,
    category_name TEXT UNIQUE NOT NULL
);

CREATE TABLE books (
    book_id     INTEGER PRIMARY KEY,
    title       TEXT NOT NULL,
    price_gbp   REAL NOT NULL,
    price_inr   REAL NOT NULL,
    rating      INTEGER NOT NULL CHECK (rating BETWEEN 1 AND 5),
    in_stock    INTEGER NOT NULL CHECK (in_stock IN (0,1)),
    category_id INTEGER NOT NULL REFERENCES categories(category_id)
);
```

Loaded result: **163 books across 5 categories**.

## SQL queries (all in `queries.ipynb`, run against `books.db`)
| # | Demonstrates | Query |
|---|---|---|
| Q1 | SELECT / WHERE | 5-star, in-stock books, ordered by price |
| Q2 | ORDER BY / LIMIT | Top 10 books by rating, then price (INR) |
| Q3 | DISTINCT | Distinct rating values present |
| Q4 | IN / BETWEEN | 4–5 star books priced £10–£30 |
| Q5 | JOIN | 4+ star books joined to their category name |

Each query's SQL text and its result table are printed in the notebook.

## SQL vs. pandas equivalence
Q2 and Q5 are re-read into DataFrames with `pd.read_sql`. Separately, `books_df` and
`cats_df` (each pulled once via `pd.read_sql`) are joined in memory with `pd.merge` on
`category_id`, filtered to `rating >= 4`, and sorted to match Q5's `ORDER BY`. The two
results are compared column-by-column with `.equals()` — **confirmed identical** — and
backed by an `assert` in the notebook.

## Known limitations
- `PRAGMA foreign_keys = ON` is not set, so SQLite does not enforce the FK constraint at
  insert time (the loaded data is clean, so this had no effect here).
- The scraper has no retry/backoff around HTTP requests; a transient network failure would
  raise rather than retry. Field-level parse failures, which the spec asks about, are handled
  as described above.
